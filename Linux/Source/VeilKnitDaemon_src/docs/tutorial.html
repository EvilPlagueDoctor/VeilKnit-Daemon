Building your first Daemon Network app

This walkthrough creates a small Rust application, performs first-run user approval, prints the local identity, sends text, and listens for messages. The app never opens a Veilid route or DHT directly.

1. Create a project

cargo new my_network_app
cd my_network_app

The SDK is asynchronous, so the examples use Tokio.

2. Add the SDK

While the SDK lives beside your project, add it by path:

[dependencies]
daemon_network_sdk = { path = "../A_Daemon_Network/crates/daemon_network_sdk" }
tokio = { version = "1", features = ["full"] }

Copying only lib.rs is not recommended. Depending on the crate keeps its manifest, examples, future modules, and version together. If the crate is published later, the path dependency can become a normal version dependency.

3. Connect and authorize

Replace src/main.rs with:

use daemon_network_sdk::{ClientError, NetworkApp};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let app = match NetworkApp::builder("example.my-app")
        .display_name("My First Network App")
        .connect()
        .await
    {
        Ok(app) => app,
        Err(ClientError::AuthorizationRequired(request)) => {
            println!("Approve this app in the daemon:");
            println!("  {}", request.approval_command());
            request.wait().await?
        }
        Err(error) => return Err(error.into()),
    };

    println!("Connected as {}", app.local_user().identity);
    Ok(())
}

Start and log into veilid_test_node.exe, then run your app:

cargo run

On the first run the app prints a command similar to:

app-approve 1

In the daemon console you may inspect requests first:

app-pending
app-approve 1

The requesting process retrieves the new credential using its private request token, stores it under %LOCALAPPDATA%\DaemonNetwork\credentials, and completes authentication. Later launches connect without prompting.

Lost credential: if the daemon says the app is already registered but the SDK cannot find its credential, run app-rotate in the daemon and relaunch or use the manual credential workflow.

4. Share identities

The local identity is available as a typed value:

println!("Share this identity: {}", app.local_user().identity);

Parse an identity received through a room key, QR code, contact file, or another trusted channel:

use daemon_network_sdk::NetworkIdentity;

let friend: NetworkIdentity = copied_text.parse()?;

The current SDK intentionally does not expose global username search. Applications decide how invitations and contact exchange should work.

5. Send a message

let receipt = app.send_text(&friend, "Hello from my app!").await?;
println!("Daemon accepted message {}", receipt.message_id);

The daemon attempts immediate encrypted delivery through an established handshake. If that cannot be completed, it queues the same application payload through the mailbox system. Your app does not change code for offline users.

For binary formats, serialize your own packet and use send:

let packet = serde_json::to_vec(&my_packet)?;
app.send(&friend, packet).await?;

6. Receive messages

let mut messages = app.subscribe().await?;

loop {
    let message = messages.next().await?;
    match message.text() {
        Ok(text) => println!("{}: {}", message.sender.short_id(), text),
        Err(_) => println!("{} sent {} bytes", message.sender, message.payload.len()),
    }
}

The stream is filtered by authenticated app ID. Messages retrieved while your app was closed are queued by the daemon and replayed when the subscription reconnects, subject to daemon queue limits.

You can also request an immediate offline scan:

app.retrieve_mail().await?;

7. Request and respond

Use a conversation ID when one message expects a reply:

let request = app.request(&friend, b"What is your status?").await?;
println!("Conversation: {:02x?}", request.conversation_id);

On the receiving side:

let incoming = messages.next().await?;
if incoming.conversation_id.is_some() {
    app.respond(&incoming, b"Online").await?;
}

respond sends to the authenticated transport sender and preserves the incoming conversation ID.

8. Broadcast to a group

let recipients = vec![alice, bob, carol];
let deliveries = app.broadcast(recipients, b"Meeting starts now").await;

for delivery in deliveries {
    if let Some(error) = delivery.error {
        eprintln!("{} failed: {}", delivery.recipient, error);
    }
}

broadcast is bounded to 16 simultaneous sends. For very large rooms, build a room protocol or future paged/gossip transport rather than unbounded fan-out.

Custom delivery options

use daemon_network_sdk::{MessageOptions, NetworkApp};

let options = MessageOptions {
    conversation_id: Some(room_id),
    expires_at: Some(unix_expiry),
    await_response: false,
};
app.send_with_options(&friend, packet, options).await?;

Handling common errors

ErrorMeaningAction
DaemonEndpointNotFoundNo endpoint discovery file and no environment override.Start and log into the daemon. Confirm both programs run under the same Windows user.
AuthorizationRequiredThis app has no credential yet.Show the command and wait for approval.
CredentialNotFoundThe daemon remembers the app but its secret is unavailable locally.Rotate the credential in the daemon.
ProtocolA capability was denied or an operation failed.Display the daemon's code and message; do not retry blindly.
SubscriptionClosedThe daemon stopped or restarted.Reconnect and open a new subscription.

9. Build and ship without Rust installed

cargo build --release

Distribute target\release\my_network_app.exe. The destination computer does not need Rust or Cargo. It does need its own running daemon, and each app installation must be approved against that computer's daemon identity store.

Applications should not ship another user's credential file. Credentials identify a local app installation and must be created or approved locally.

Useful environment overrides

VariableUse
DAEMON_NETWORK_ENDPOINTExplicit named-pipe or Unix-socket endpoint.
DAEMON_NETWORK_CREDENTIALExact credential JSON file.
DAEMON_NETWORK_CREDENTIAL_DIRDirectory for automatic credential loading and first-run storage.

Next steps

  • Use Serde to define an application packet with its own protocol version.
  • Deduplicate application-level packet IDs when direct and mailbox paths may overlap.
  • Keep room membership and user-facing history in the app, not in the transport SDK.
  • Use the advanced client only when the high-level API does not expose a required daemon feature.
